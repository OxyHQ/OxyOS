# macOS parity

This page condenses five research reports written on 10 November 2026 against main at `e388598a`:
**saturation** (why macOS never feels loaded), **robustness** (why nothing ever seems to break),
**fluidity** (why motion never stutters), **details** (why it looks compact and professional) and
**code** (how the codebase must be shaped to get there). Device evidence comes from the ThinkPad
P14s Gen 3 (read only, with a person signed in) and from seldon. The roadmap below merges the
five reports' rankings into one list, and the last table says who owns each item. Keep that table
current: whoever opens a pull request for an item updates its row in the same pull request.

**Correction.** The robustness report says the ThinkPad has no swap. It does: 22 GB of disk swap
(`/dev/nvme0n1p4`) is active. What it lacks is compression in front of that swap (zswap is off, no
zram), working-set protection, a pressure signal to apps and an OOM policy that protects the
compositor. The memory item (S6) below is written with that correction, and it prefers zswap over
zram because a disk swap exists.

## The short version

| --- | --- | --- |
| Saturation | Every thread carries a declared urgency (QoS class, task role) and **every** resource enforces it: the CPU scheduler, disk I/O tiers, timer coalescing, memory (compressor, swap, pressure notifications, jetsam), heat. The window server is in a reserved priority band and sets each app's role. | The right intent in places (the search crawler at `SCHED_IDLE`, backups at the idle class, hosts with 0 wakeups when idle, Low Power Mode), but no structure: the compositor, the shell and every app share one logind scope at nice 0; hidden apps are never throttled; nothing reacts to memory pressure; two "idle" settings are defeated by the platform (the NVMe's `none` scheduler ignores I/O priority; backupd is idle only inside `system.slice`). ## Saturation

macOS maps one QoS class onto every resource in one table (XNU `thread_qos_policy_params`): base
priority 46 (47 in the frontmost app) down to 4 for background, I/O tier 0–3, timer latency tier
0–3. The clutch scheduler picks QoS buckets by earliest deadline (0 ms for user-interactive, 250 ms
for background), and ranks apps inside a bucket by interactivity. WindowServer runs at
`BASEPRI_GRAPHICS` 76, above every app thread (63 at most). App Nap lowers a hidden, silent app's
priority, timers and I/O, and lifts it at once on foreground or IPC. Memory goes compressor, then
swap, then pressure notifications, then jetsam or the "out of application memory" sheet.

On Debian trixie's 6.12 kernel every one of these has an equivalent: cgroup v2 `cpu.weight` per
app scope (the thread group), `cpu.idle` for background groups, the EEVDF slice hint for a shorter
deadline, rtkit for high priority, `preempt=full` (a `PREEMPT_DYNAMIC` switch), mq-deadline or
io.cost for I/O priority, zswap, MGLRU `min_ttl_ms`, `memory.min/low/high`, PSI triggers and
systemd-oomd. Not available: uclamp and sched_ext are not built.

Two Linux traps decide the design: nice and `SCHED_IDLE` only order tasks **inside one cgroup**
(between cgroups only weights count), and I/O priority is a hint to the elevator, ignored by `none`
and never applied to buffered writeback.

What the ThinkPad shows (6.12.101, systemd 257.13, i5-1240P with P-cores 0–7 and E-cores 8–15, 40 GB
RAM, 22 GB swap):

- Everything OxyOS draws is in `session-3.scope`, TS nice 0, no rtkit, no `CAP_SYS_NICE`, no Vulkan
  global priority, voluntary preemption.
- ADR 0051 decision 13's premise ("no user manager") is false: `user@1002.service` runs with
  `Delegate=yes` (cpu, memory, pids), its own `session.slice` and `app.slice`. The session does not
  use it.
- `system.slice` has no cpu subtree, so backupd's idle threads sit in a group that competes with the
  whole `user.slice` at equal weight. Another user's slice (two game servers) competes with the
  signed-in person at equal weight.
- Hidden apps are not told they are hidden (`docs/performance.mdx`, What remains) and keep their
  frame clock, animations and timers at full priority.
- zswap off, no zram, `min_ttl_ms` 0, `memory.low/min/high` unset everywhere, no systemd-oomd; the
  session reads PSI only to show it in Activity Monitor.
- There is no load mode in `perf.py`, and input time is the host's, not the device's.

## Robustness

| macOS mechanism | OxyOS today | Gap |
| --- | --- | --- |
| Separate processes; a crash ends one | Apps, shell, search, reader, services separate; compositor, launcher and supervisor are one process | A session crash ends everything |
| launchd KeepAlive, throttled, never gives up | systemd `Restart=on-failure` with the default start limit; the login program 5 in 30 s, then the console | Services and the login screen can die for good; the login restart is a fixed 1 s, not the doubling ADR 0061 promises |
| Wait cursor over a hung app in about 2 s; ⌥⌘⎋ Force Quit always responsive | Ping after input, 5 s, Force Quit only in the Dock menu | No cursor, no title mark, no window, no shortcut, no hang report |
| Dock and Finder relaunched | Shell restarted with a doubling wait (crash only) | A hung shell is not detected; a shell dying at start ends the session |
| watchdogd ends a hung WindowServer | None; the power key is held by the session's inhibitor | A hung session is a hung machine |
| ReportCrash for every process | Bloom apps only; no coredump; `LimitCORE=0` | System processes leave no trace |
| Kernel panic: restart and "restarted because of a problem" | `kernel.panic=0`, no watchdog, no pstore data | Hangs forever (the 1 November NVIDIA freeze left nothing) |
| Resume and window restoration after any end | Reopen on an orderly logout only, app ids only | An unclean end restores nothing; no window state |
| Autosave and Versions | Crash-safe key-value storage and preferences | No document versions |
| Compressor, swap, "out of application memory" | 22 GB disk swap, nothing in front of it; one scope; `oom_score_adj` 0 for the compositor | The OOM killer is as likely to pick the compositor as the runaway app |
| Signed System Volume, snapshot boot, atomic updates | A/B `/usr` with dm-verity chosen (ADR 0023 decision 6), its ADR not written; development deploys swap file by file | Not yet |

## Details

The ten highest-impact fixes, from the details report (macOS 27's choices where they differ from
Tahoe's; the full-width Dock shelf and Super as the system's ⌘ are owner decisions not reopened):

1. Every frontmost app gets its own bold app menu (About, Settings…, Hide, Hide Others, Show All,
   Quit), and system apps declare standard menus. Today a window with no menus leaves "OxyOS · Ver".
2. One text system: 13 pt base, per-size tracking, label/secondary/tertiary/quaternary alphas.
3. Neutral surfaces and one accent, only for selection, the default button, the focus ring and an
   on switch (today purple, a fixed blue, green and near-black all act as primary).
4. Menu metrics and one menu style: rows about 22–24, 13 pt, content-sized width, accent highlight,
   arrow cursor, a right-aligned shortcut column, a visible shadow.
5. Real materials: blur behind every shell panel (`glass()` changes only alpha; the blur engine
   exists, `LockClock` uses it).
6. Settings in compact macOS form density (section radius about 10, rows about 36–40, hairline
   separators, mini switches, Title Case section titles, a sidebar search field).
7. One alert component: content-sized, default trailing and accent-filled, Cancel never default, the
   app's icon, Return answering OK-only notices.
8. Standard shortcuts (Hide Others, Show All, Force Quit, minimize and close all, Dock toggle,
   tiling) and one localized chord notation in a fixed modifier order and aligned column.
9. Wording: one term for Log Out, one wrong-password message, US spelling, typographic apostrophes,
   ellipses where a command asks first; in Spanish one "Ajustes del Sistema", no "pantalla de inicio" for the login
   window (it reads as the Home Screen), agreement fixes.
10. Interaction states: a native focus ring, hover distinct from selection, one disabled alpha,
    tooltips after about 1 s, the arrow cursor except on links.

## Code

The code report's measurements: 290,701 lines of Rust in 58 workspace members, 35,195 of C++, 69,410
of TS/JS, 12,945 of Python. The crate graph has 9 inversions (the app runtime `client-ffi` links the
account service and its keychain crypto, `boot-logo` links the whole compositor, `offscreen` links
the `backupd` binary crate, `controls`/`sound`/`speech` take domain types from the display
protocol, five crates depend on `oxyos-install` only for its socket). Concepts with several owners:
the service socket (×4), the application-id rule (×4, two different rules), passwd lookups (×6,
some through NSS, some reading the file), POSIX locale parsing (×5), `Secret` (×4, two not
zeroized), text chunking (×4 plus 15 inline), JSON escaping (×2). Mirrored by hand: the protocol's
version tables, the 2,481-line C header, the TS session-state types. Two god objects: `Compositor`
and `Scene`, 88 fields each.

The report's plan, in phases: 0 stop the bleeding (lint every language with a baseline, check the
layering, workspace dependencies, the `rn-host-spike` rename), 1 the scenario contract as one serde
codec (regress.py and launch.rs are the two most-changed files), 2 one owner per concept, 3 generate
what is mirrored, 4 the host and the apps' layout, 5 the god objects. Behaviour stays the same in
every pull request, moves are separate from edits, and moves of hot files land in quiet windows.
