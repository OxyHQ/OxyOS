# Build and verify the native foundation

The root Rust workspace is independent of the `config/` image configuration. It has no third-party Cargo dependencies and does not load a display toolkit. It currently verifies protocol, policy and ownership state; it draws no pixels.

Requirements: Rust from `rust-toolchain.toml`, a native linker and Python 3. Linux is the target. Unix socket tests also run on macOS for development; Windows is not currently supported.

```sh
cargo fmt --all --check
cargo test --workspace --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
python3 scripts/check-native-boundary.py
cargo run --locked -p oxy-platform-probe
```

The probe launches two independent client processes that speak protocol version 2 over Unix sockets to one shared compositor `Scene`. Each creates a toplevel and presents three frames; one also opens a popup larger than its window, checks that the compositor placed it beyond all four parent edges, and waits for its buffer to be released after destroying it. The probe then requires that no surface, client or held buffer remains. It uses a private temporary directory, socket timeouts, connection/exit deadlines and child cleanup. No DISPLAY/WAYLAND_DISPLAY is passed to its children. Completion is synthetic and labeled `Clock::Synthetic`. The probe is a finite developer tool, not an installed service or authenticated compositor.

Expected result:

```json
{"mode":"headless-metadata","protocol":2,"clients":2,"frames":7,"popups_beyond_parent":1,"graphics":false,"bloom":false,"status":"passed"}
```

| `crates/oxy-compositor-core/src/scene.rs` | Roles, grants, ownership, quotas, stacking, input routing, popup grabs, focus, lock primitive, outputs, frame lifecycle and buffer release |

| `.github/workflows/native-ci.yml` | Formatting, tests, Clippy, dependency-boundary check and probe on Linux |

Decisions and policies (roles, coordinates, grabs, outside press, dismissal, lock, buffer lifetime) are in [ADR 0001](./adr/0001-native-platform-boundaries).

Tests cover: every message round trip; every truncation; length mismatches; 200,000 deterministic fuzzed streams (bit flips, truncation, random bytes, trailing garbage) that must never panic and may only decode re-encodable messages; separate request/event decoders; invalid field values; version negotiation; invalid connection order. Scene tests cover popups beyond all four parent edges, ready-content-only mapping, connection-local parenting, forged roles and grants, depth and surface quotas, stale and foreign grab serials, nested submenu chains and focus return, consumed outside presses, trigger re-press, input over another application's region, press-drag-release, parent move without detached jumps and reconstraint, minimize/destroy/disconnect, shell failure, 500 popup and 200 client lifecycles settling every count, lock covering outputs and surviving a lock UI crash, work areas and input regions, overlays above fullscreen and direct-scanout eligibility, shortcuts with a stalled client, stale configures during resize, touch and capture cancellation, modal dialogs, output scale change and removal, and grant revocation.

## Wire contract (version 2, experimental)

Each packet is a 4-byte little-endian payload length followed by one opcode byte and fixed-width little-endian fields. Payload length is 1–64 bytes. Requests (client → compositor) and events (compositor → client) have separate opcode spaces and decoders. The table is generated from `crates/oxy-protocol/src/schema.rs`; a test fails if this table and the schema differ.

Field rules: sizes are 1–16,384; coordinates and offsets are within ±2^20; booleans are 0 or 1; enums and adjustment flags reject unknown values; anchor rectangles have a positive size; surface id 0 is invalid. Encoders run the decoder's validation, so a peer never emits what it would reject. Pointer and touch coordinates are surface-local logical pixels in 24.8 fixed point. Scale is in 120ths.

The connection starts with Hello (a version range) answered by Welcome (the highest common version) or ProtocolError; anything before Hello, a second Hello or anything after Goodbye is `InvalidOrder` and closes the connection. A protocol error closes the connection and the compositor removes every resource of that client. These messages carry no pixels, file descriptors or privileges.

Not yet in the contract: file-descriptor passing and buffer import, formats/modifiers, GPU fences, per-consumer release, keyboard keymaps, IME, clipboard, accessibility bridging and output enumeration events. Do not freeze version 2 as an SDK ABI.

## Core state transitions

`Presentation::submit` validates current configure, dimensions, increasing sequence and buffer availability before mutation. One replacement is queued; superseding it returns its metadata so a backend can retire that resource. `begin_present` moves the queue to an in-flight slot. Only `complete_present` updates displayed content and returns the previous metadata. `retry_present` retains existing displayed content, retries the current submission or yields to a newer valid queued frame.

The caller must establish GPU readiness before begin and actual output completion before complete. Returning metadata is not a GPU fence or permission to reuse a buffer still consumed elsewhere. The `Scene` retires every held buffer of a destroyed or dismissed surface, deferring releases requested during an in-flight frame to `end_frame`; it still knows nothing about GPU fences. Multi-output references are not implemented.

## Scope and next gate

Not implemented: DRM/KMS, Vulkan, buffer FD import, a compositor process with device input, text, Bloom host, graphics, secure session, bootable image or hardware performance evidence. Input routing and the lock exist only as tested policy driven by tests and the probe. No empty renderer/service crates or success-returning stubs are included.

Next gate: implement and measure the first hardware render/import/present path and the Bloom host feasibility sample described in the architecture and audit documents. The image must not turn this probe into the session executable ([Base image configuration](./iso-build)).
