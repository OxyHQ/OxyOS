# React Native's Android implementation on OxyOS

OxyOS is not Android. The native Bloom host (`tools/rn-host-spike`) nevertheless runs **React Native's own modules in their Android implementation**. React Native supports two native platforms, and the host implements the native interfaces of one of them, Android, instead of maintaining copies of React Native's platform branches. This page is the contract for that adaptation.

**Rule:** a React Native API that OxyOS does not provide fails visibly. Its native module is absent and the call throws, or its promise rejects. It never pretends to succeed and never leaves its caller waiting. Where React Native's own Android code would skip a missing module silently, OxyOS overrides it to fail (`sample/oxyos/`).

`scenarios/android-adaptation.json` (`regress.py`; the probe is `sample/AndroidProbe.tsx`) checks one call per row:
- **unavailable:** `ToastAndroid`, `Vibration`, `PermissionsAndroid`, `Share`, `Alert.alert`, `Alert.prompt` and `getAndroidID`;
- **rejected:** `Image.getSize` of a remote image and `Linking.openURL`;
- **answered:** `AccessibilityInfo`'s timeout and screen reader, `Appearance`, `Dimensions`, `I18nManager.isRTL` and `AppState`;
- **accepted with no effect:** `StatusBar.setHidden`, `I18nManager.forceRTL` and `Appearance.setColorScheme`.

Rows not in this list are not checked.

`scenarios/network.json` (the probe is `sample/NetworkProbe.tsx`, against a local server `regress.py` runs) checks `fetch` and `XMLHttpRequest`: JSON, text, a 404, request and response headers, a POST body, a redirect, bytes read back as an `ArrayBuffer`, a multipart form, an abort, a refused connection, a timeout, and a text body as it arrives with a character split between two reads. A file in a multipart body fails visibly.

`scenarios/expo-modules.json` (the probe is `sample/ExpoProbe.tsx`) checks what an Expo application's platform modules answer, through each package's own API: AsyncStorage (a value an earlier run kept read back from the application's data directory, values written, merged, listed and removed, and the file holding exactly what is left), NetInfo, expo-crypto, expo-secure-store, expo-haptics, `Linking` and expo-linking, and expo-constants. `scenarios/stash.json` and `scenarios/stash-scaled.json` run Stash from its own checkout ([below](#expo-applications-from-their-own-checkout)) on a home of the run's own: its first window, its view switch, Oxy Files signed out and the Trash. `scenarios/stash-files.json` and `stash-files-scaled.json` work in it as a person does in a file manager, checking the assistive technology's nodes, the focus, the presses and the disk at every step: selection by a press, Shift and Ctrl, a double press opening a folder, a file another program writes appearing at once, renaming in place with the stem selected, New Folder, Move to Trash and Put Back, and a context menu at a secondary press. Stash is the development registry's `so.oxy.stash`, first in the dock.

## What is reused from React Native's Android implementation

| Part | How |
| --- | --- |
| Core JavaScript | React Native's own modules resolve `Platform.android.js` and take their Android branches. Their `.android.js` files are used where no OxyOS override exists (`sample/metro.config.js`). Everything else, including the `Platform` that `react-native` exports to apps and to Bloom, reports `oxyos`. |
| Native component names, view configs and commands | `AndroidTextInput` (Bloom's `TextField`), `AndroidHorizontalScrollView` (the `ScrollView` component) and `AndroidHorizontalScrollContentView`. |
| C++ shadow nodes, props and state | The Android text input's, built unchanged from a private copy patched with the `RN_SERIALIZABLE_STATE` guard upstream lacks (`patches/`). The horizontal scroll content view's is built unchanged. |
| TurboModule specs | The Android specs (for example `PlatformConstants`), answered by the host's own modules below. |
| Events | Android's text-input events (`topChange`, `topKeyPress`, `topSelectionChange`, `topSubmitEditing`, `topFocus`, `topBlur`, `topEndEditing`) with Android's payloads. |
| Touchpad pinch (`input.h`) | As Android 14's touchpad stack gives one to applications (inputflinger's `GestureConverter`): two fingers around the pointer, starting `INITIAL_PINCH_SEPARATION_PX` (200 of the display's pixels) apart side by side, finger 0 down then finger 1, both moving as the spread changes, then finger 1 up and finger 0 up, as touches to React Native (the target under finger 0) and as fingers (RNGH's pointer type 0) to gesture handlers. One difference, stated: Android's fingers never turn, and these turn as libinput reports the user's fingers turning, so rotation handlers see a touchpad's twist. A pinch libinput cancels cancels both fingers. `scenarios/pinch.json` checks it. |
| Assets | Android's resource layout (`drawable-*`, `raw/`), computed by React Native's own path helpers. |
| Release bundle | Hermes bytecode, as an Android release build ships it: Metro's output compiled by the `hermesc` of the Hermes the host runs, with the Android Gradle plugin's `-emit-binary -O`. An application's package carries its source bundle and the machine compiles it with its runtime's `hermesc` into `index.hbc` ([ADR 0030](./adr/0030-installing-applications), decision 1: Hermes runs bytecode as trusted input); the host runs the bytecode and its JavaScript knows it by its source's URL (`SourceCode.scriptURL`), beside which its assets are. Each application is a bundle of its own (`sample/entries/`, `sample/packages.mjs`), built against its runtime's framework (React Native's JavaScript, React, Bloom and the native packages' JavaScript, compiled once into the runtime, `sample/framework.mjs`; decision 17), which the host maps and evaluates before it; the probes are one development bundle against it too (`sample/index.js`, `bundle.mjs` with `HERMESC`). A source bundle still runs, but Hermes then parses and compiles it while the app starts. Stack traces give bytecode offsets, as an Android release build's do without its source map. |

## What OxyOS implements

| Module | OxyOS behavior |
| --- | --- |
| `PlatformConstants` | `Release`/`Model` are `OxyOS`. `Version` is 36: not a device API level, but the level whose React Native code paths the host follows (React Native 0.88's target SDK). Core uses it only to trust keyboard events, and OxyOS has no software keyboard and sends none. `getAndroidID` throws ("OxyOS has no Android ID"). |
| `DeviceInfo`, `SourceCode`, `AppState`, `Appearance` | The window's size and scale; the bundle URL; always active; the light scheme. |
| `AccessibilityInfo` | Reports no assistive technology. Reduced motion is the session's Reduce Motion ([ADR 0019](./adr/0019-settings)): `isReduceMotionEnabled`, and `reduceMotionChanged` as it changes, as Android tells its animator duration scale. Reanimated reads it too: the host gives it the setting when JavaScript installs it (`_REANIMATED_IS_REDUCED_MOTION`, as Android's NativeProxy reads its animator scale), and its reduced-motion module's OxyOS variant (`sample/oxyos/react-native-reanimated/`, which Metro resolves as it resolves React Native's) follows each change, so `useReducedMotion()` renders again and an animation with `ReduceMotion.System` (the default) jumps to its end from the next one on, no restart; a `ReducedMotionConfig` holds its mode while it is mounted, `System` following the session (`scenarios/reanimated-reduce-motion.json`). The recommended timeout is the one asked about, as on Android without a preference. `sendAccessibilityEvent(view, 'focus')` (through Fabric) moves the host's accessibility focus, as Android's accessibility focus: to the view, or to the first accessible node inside it. The host publishes each surface's tree to the compositor for a screen reader ([ADR 0003](./adr/0003-accessibility-protocol)), and a screen reader's activation reaches JavaScript as Android's accessibility click (`onClick`, which Pressability turns into `onPress`). `announceForAccessibility` reaches the screen reader through the compositor, at once; its other actions (increment, decrement, custom actions by name, scrolling, dismissing, a selection) reach JavaScript as Android performs them ([ADR 0003](./adr/0003-accessibility-protocol)). |
| `Intl` (`intl.h`, `crates/oxyos-intl`) | Hermes has `Intl` on Android from the platform; OxyOS's Hermes has none, so the host installs one before the bundle runs: `Intl.DateTimeFormat` and `Intl.NumberFormat` (`format`, `formatToParts`, `resolvedOptions`, `supportedLocalesOf`), `Intl.getCanonicalLocales`, and `Date`'s and `Number`'s `toLocale*String` built on them, with ECMA-402's option processing (`intl.js`) and ICU4X's CLDR data for the formatting. The default locale is the session's (`LC_ALL`, `LC_MESSAGES`, `LANG`), the default time zone the system's, and named time zones come from the system's tz database. An option not supported yet (such as compact notation or `timeZoneName`) throws a `RangeError` saying so; `Collator`, `PluralRules`, `RelativeTimeFormat`, `DisplayNames`, `Locale`, `ListFormat` and `Segmenter` are not provided yet and are undefined, so feature detection finds them absent. Differences from ICU's own formatting, from ICU4X 2: a format has one width (taken from `month`, else `weekday`, else `era`) where ECMA-402 gives each field its own, and the month's text or number follows the locale's date lengths (German's `{ day: 'numeric', month: 'short' }` is `29.10.`, not `29. Okt.`); digits are always Latin and the calendar Gregorian; `useGrouping: 'always'` groups as `auto`. `scenarios/intl.json` checks every row against ICU 78.3 with CLDR 48 (Node's `formatToParts`), the German one as that difference. |
| `ExceptionsManager` | Prints the error and its stack. |
| `Image` | What Android's `ReactImageView` does: each mounted Image loads its source, at the size it is drawn, on threads of its own (`crates/oxyos-image`, PNG and JPEG decoded in Rust, an embedded ICC profile such as Display P3 converted to sRGB, reduced by averaging), and the view draws it by `resizeMode` (`cover`, `contain`, `stretch`, `center`, `repeat`, `none`), rounded with its corners and tinted with `tintColor` as Android's `SRC_IN` filter. Its load events are Android's: only when JavaScript listens (`shouldNotifyLoadEvents`), `loadStart`, then `load` with the bitmap's size in pixels or `error`, then `loadEnd`. Views showing the same picture share it. Sources are files: `file://` (a release bundle's assets, resolved to its drawable folders, as Android resolves them when the bundle is loaded from the file system) and absolute paths. Not supported yet, and failing with a message: remote images, `data:` URIs and other formats (GIF, WebP). `blurRadius` blurs it as Fresco does (Drawing, below). A truncated JPEG shows what arrived, as Android's decoder does. `scenarios/images.json` checks the events and the output's pixels. |
| `ImageLoader` | `getSize` and `getSizeWithHeaders` read a file's headers; `prefetchImage` succeeds for a readable local image, which needs no fetching; `queryCache` reports nothing cached; `abortRequest` has nothing to abort. Remote images are refused, as above. |
| `Networking` (`fetch`, `XMLHttpRequest`) | Requests run in Rust (`crates/oxyos-net`, through the host's one Rust library): TLS with rustls against the system's certificates, gzip and brotli, a timeout over the whole request, and one cookie jar for the process, used only by requests `withCredentials`. Redirects are followed as browsers do (up to 20; a 303, or a 301 or 302 after a POST, goes on as a GET without its body; `Authorization` is not carried to another origin), and each hop keeps and sends its own cookies. A connection lost before any response is tried again, up to three times, as Android's OkHttp does. The answers are Android's events, each with its arguments as one array; an incremental body (text only, as on Android) never splits a character. What was sent of a body is told as it goes (`didSendNetworkData`), as Android's `ProgressRequestBody` tells it. A multipart form's file part (`{uri, name, type}`, which needs its type, as on Android) and a body from a URI are read from the file as they are sent, never wholly in memory, with their length; a `file://` file is opened through the file service's scope ([ADR 0028](./adr/0028-file-access)), in an application's window only, and one outside it fails the request with the reason; a `data:` URI's base64 is its bytes; any other URI (the network's, `content://`) fails the request. Every failure's reason is logged (`[host] network request N failed: ...`), since `fetch` reports only "Network request failed". The jar has no public suffix list, so a cookie for a whole public suffix is not refused. |
| Expo modules (`sample/oxyos/expo-adapter.js`) | `expo-constants`: the public app config the application's build embedded (null without one, as on Android without `app.config`), a bare build's execution environment, no status bar, the computer's name and the system's version. `expo-crypto`: `getRandomValues` and `randomUUID` from the kernel's CSPRNG (`getrandom`), SHA-1, SHA-256, SHA-384 and SHA-512 digests (ring); MD2, MD4 and MD5 throw naming the algorithm, and its AES-GCM classes and functions throw when used, so the rest of the package loads. Expo's own UUIDs come from the CSPRNG too. `expo-linking`: the linking URL is what the session started the application to open, as `Linking`'s initial URL; none for a plain launch, and none arrives later. `expo-haptics`: resolves without effect, as Expo's own implementation does on a desktop that has no haptics; Android's `performHapticsAsync` is not provided. `expo-secure-store`: OxyOS keeps no secrets for applications, because the machine's Oxy account is the platform's ([ADR 0020](./adr/0020-oxy-account-login), decision 6) and its session for applications is not available yet: a read finds nothing (and says why, once, in the log: the Oxy SDK then starts signed out), a delete leaves nothing, and keeping a value rejects with the reason. The module is there rather than missing so that what an application keeps in it never falls back to plain storage (the Oxy SDK falls back to AsyncStorage without it). `expo-web-browser`: OxyOS has no web browser yet, so opening a page or an authentication session rejects with that reason; dismissing, with nothing open, does nothing. `@expo/app-integrity`: App Attest and Play Integrity are iOS's and Android's, and the package's own functions say so on any other platform (its web module is empty, and so is OxyOS's): OxyOS cannot prove an application's identity to a server yet (the Oxy SDK asks for an assertion only on iOS and Android). `expo-font` and `expo-asset` load bundled files. `expo-clipboard` is the OS clipboard ([ADR 0007](./adr/0007-clipboard)): its calls carry the serial of the latest key or press the app received, so they work only while the app has focus and the user just acted (a refused read gives ""); URLs are text and images are refused; `onClipboardChanged` fires when the content changes. `expo-notifications` posts to the session ([ADR 0026](./adr/0026-notifications)): notifications presented now (a `null` trigger) with their data and a category's actions, the handler asked as Expo asks it, responses to the listeners and `getLastNotificationResponse` once each; scheduled triggers, push tokens and background tasks are refused. `expo/fetch` is not provided: bundles for OxyOS set Expo's `EXPO_PUBLIC_USE_RN_FETCH=1`, so `fetch` is React Native's, above. `EXPO_PUBLIC_*` variables are inlined when the bundle is built, as Expo's production build inlines them. Expo's native views come through `getViewConfig`: `expo-blur`'s views are host components (below), and any other Expo view fails with a message naming it. |
| `expo-file-system` (`sample/oxyos/expo-file-system.js`, `files.h`, [ADR 0028](./adr/0028-file-access)) | The `FileSystem` native module as its Android implementation behaves, over the host's `OxyOSFiles` (`crates/oxyos-files`), for an application's window (in the shell and the login screen every call fails, saying so). `File` and `Directory` (`exists`, `size`, `type`, `lastModified`, `creationTime`, `md5`, `info`, `text`, `base64`, `bytes` and `write` with their synchronous forms, `create`, `delete`, `copy`, `move`, `rename`, `list`, `createFile`, `createDirectory`, `digest`, `open` and its `FileHandle`), `Paths` (`document` is `$XDG_DATA_HOME/oxyos/apps/ID` and `cache` `$XDG_CACHE_HOME/oxyos/apps/ID`, where [ADR 0030](./adr/0030-installing-applications) keeps an application's data, ID the id the session's launch gave it, `OXYOS_APP_ID` (`application.h`); an application the session did not start (`OXYOS_APP_UNRECORDED`) has none, and they say why; `bundle` its bundle's folder, read-only; the disk's space), watchers (`created`, `modified`, `deleted`, `renamed` with both paths, debounced, as Android's), downloads (into a folder named by the response, refused over a file unless `idempotent`, with progress, cancelling, and a task's pause and resume with `Range`) and uploads (the file as the body or in a multipart form, with progress). Synchronous methods run on the JavaScript thread, as on Android; asynchronous ones on the service's thread. A URI outside the scope fails as Android's missing permission does (`ERR_INVALID_PERMISSION`), with the reason. Not available yet, and failing: the file and folder pickers (`File.pickFileAsync`, which Expo answers as a cancelled pick, says so in the log), `preview` (`canPreview` is false), and of `expo-file-system/legacy` all but its folders and its uploads (`uploadAsync`, `createUploadTask`), which the Oxy SDK's native upload uses. `scenarios/file-system.json` checks it on a home of its own, and `scenarios/file-system-unrecorded.json` an application the session did not start. |
| The application (`OxyOSApplication`, `application.h`) | What the host runs: its id, the registry entry's (`so.oxy.stash`), which the session gives it in `OXYOS_APP_ID` (an application the session did not start, `OXYOS_APP_UNRECORDED`, has it only as a claim; one started with none has none); its module (`X-OxyOS-Bloom-Module`); its own directories by that id, `oxyos/apps/ID` under `$XDG_DATA_HOME` (what it keeps) and `$XDG_CACHE_HOME` (`crates/oxyos-apps`, as [ADR 0030](./adr/0030-installing-applications) places them), only when the session started it, so a claimed id never reaches another application's data (ADR 0030's verified launches will narrow this to installed applications); and the public Expo config its build embedded beside the bundle (`applications/MODULE/app.config`), as an Android build embeds `app.config` in the APK's assets. `regress.py` gives every run XDG directories of its own. |
| `RNCAsyncStorage` (`@react-native-async-storage/async-storage`) | Kept in the application's data directory (`async-storage.json`, `crates/oxyos-app-storage`): replaced whole and atomically on every change, under `flock`, read again when another process of the application changed it, so two windows lose nothing. Requests run in order on a thread of their own, as Android's serial executor runs them, and answer with Android's callbacks; `mergeItem` deep-merges JSON objects as Android does and fails, changing nothing, for a value that is not one. Without directories (no id, or one the session did not give) nothing can be kept: every call fails saying so. |
| `RNCNetInfo` (`@react-native-community/netinfo`) | The machine's connectivity from the kernel (`crates/oxyos-net`), as Android's `ConnectivityManager`: connected when a default route (IPv4 or IPv6, the lowest metric) is up through an interface that is up; its type is that interface's (`wifi`, `cellular`, `vpn` for a tunnel, `ethernet`, `other`), `none` without one. `netInfo.networkStatusDidChange` follows when rtnetlink says a link, an address or a route changed and the answer is different. Whether the internet answers is NetInfo's own check over HTTP (its `reachabilityUrl`, through `Networking`). Whether a network is metered is not known on OxyOS yet: `isConnectionExpensive` is false. |
| `IntentAndroid` (`Linking`) | `getInitialURL` is what the session started the application to open, as an Android intent's data: a file (a screenshot's thumbnail pressed, [ADR 0028](./adr/0028-file-access), decision 6) or a URL of a scheme its entry declares (the dock's Trash opening Stash at `stash://trash`, [ADR 0034](./adr/0034-the-dock)); null for a plain launch. An application opens no links yet (there is no browser, and no request for one): `canOpenURL` is false and `openURL` rejects with that reason (`OxyOS has no application that opens https links yet`); `openSettings` and `sendIntent` reject too. No `url` event is ever sent. |
| `KeyboardController` and `KeyboardControllerView` (`react-native-keyboard-controller`) | As Android's with the software keyboard hidden, which on OxyOS it always is: there is none (a hardware keyboard and the input method, [ADR 0008](./adr/0008-input-method), need no room). The provider's view is a view; none of its events (the keyboard moving, the focused input's layout) is ever sent; the keyboard's corners are 0. `dismiss` takes focus from the focused input unless asked to keep it. Its input modes, preloading and the status bar's translucency have nothing to change (reported once). `setFocusTo` throws and `viewPositionInWindow` rejects: not provided yet. |
| `BlobModule`, `FileReaderModule` | Blobs are kept in the host: a response read as a blob, and blobs built from parts. `FileReader` reads them as text or as a data URL. |
| Fonts (`OxyOSFontRegistry`, for `expo-font`) | Registers a font only if FreeType can open it. |
| Text layout (`text.h`, `TextLayoutManager.cpp`) | As Android's `StaticLayout`: lines break where ICU's line break rules (UAX #14) allow, as minikin's do (after a hyphen, not between a letter and the bracket it opens), by the paragraph's break strategy (`textBreakStrategy`, for Text and TextInput alike), whose default is Android's: `highQuality` (React Native's `DEFAULT_BREAK_STRATEGY`, which its Android text input applies too). `highQuality` and `balanced` are Minikin's optimal line breaker (`OptimalLineBreaker`): of every way to break the paragraph, the one whose lines' slack squared, plus a penalty for each line (twice the hyphen penalty, 0.5 × font size × line width, × 4 at hyphenation frequency `normal`), adds up least, so a paragraph's lines are even rather than each as full as it can be; `highQuality` leaves the last line's slack free, `balanced` evens it too. `simple` breaks greedily, each line as full as it can be. A word wider than its line is broken between its characters: greedily, as many on each line as fit; optimally, at Minikin's desperate breaks (as few as can be, each costing 10¹⁰). Each paragraph between hard breaks is broken on its own, as `StaticLayout` breaks each. Hyphenation is off by default on Android for React Native (`DEFAULT_HYPHENATION_FREQUENCY` is `none`; React Native sets it on every layout, whatever the platform's own TextView default): OxyOS has no hyphenation patterns, so `android_hyphenationFrequency` `normal` or `full`, which on Android would hyphenate, hyphenates nothing and is reported once (`normal` still weighs the line penalty as Android does). At `numberOfLines`, with `ellipsizeMode` tail (the default), the last line shown holds the rest of its paragraph ellipsized at its end to fit; head and middle ellipsize when one line is shown; clip, and head or middle on more lines, cut without an ellipsis. `onTextLayout` gives each line's text as Android does (an ellipsized line's, all it stands for). A text input's text is never cut or ellipsized: it scrolls. The same paragraph at the same width is laid out once for Yoga's measurement and every frame that draws it (the last 512). Not yet: hyphenation, justified text (`textAlign: 'justify'`, which Android breaks with shrinkable spaces and no line penalty, is broken and drawn as ragged text) and bidirectional text. `scenarios/text-layout.json` and `text-layout-scaled.json` (at 1.25) check each case, the strategies with paragraphs a greedy breaker breaks otherwise, and a multiline text input's lines. |
| Fabric | View, Paragraph, ScrollView (native offsets), text input, popups (`OxyOSPopupView`), `Modal`, events, Reanimated and Worklets. A selection JavaScript sets on a text input that has no focus (`setTextAndSelection`, from its `selection` prop) is kept, as Android's `EditText` keeps it, and shown when focus comes from JavaScript (`autoFocus`, `focus()`): a field that opens with a name's stem selected (`scenarios/stash-files.json`); a press places the caret where it is instead. |
| Scrolling (`input.h`, `scroll-physics.h`) | The innermost scroll view under the pointer that can still move takes a scroll, as nested scrolling views do on Android; a text input's text first. A wheel's notch moves it its distance at once, as Android's `ScrollView` takes a wheel. A touchpad's two fingers are what Android 14 makes of them for a `ScrollView` (inputflinger's `GestureConverter`: a finger dragged): the first event begins a drag of the innermost scroll view that can move their way, or, when none can, of the innermost whose content scrolls along their axis, as Android's `ScrollView` intercepts a drag whichever way it goes once its content scrolls (`onScrollBeginDrag`), which every event then moves, and the fingers lifting (the protocol's scroll stop, libinput's) end it (`onScrollEndDrag`, with the finger's velocity, against the offset, in logical pixels per millisecond, as React Native's Android `VelocityHelper` gives it). The velocity is Android's default `VelocityTracker`'s (a second-degree least-squares fit of the last 100 ms, nothing after 40 ms still), at most 8,000 logical pixels a second; from 50 a second it flings the view as `OverScroller` flings a `ScrollView` (`SplineOverScroller`: Android's spline, its scroll friction 0.015 or one minus `decelerationRate`, a device of 160 dots per inch), stepped once a frame of the window's display. `onMomentumScrollBegin` and `onMomentumScrollEnd` frame what follows every drag, flung or not, as React Native's `handlePostTouchScrolling` frames it. A press, a wheel or new fingers stop a glide where it is, and so do fingers coming to rest on the touchpad (libinput's hold gesture, the protocol's `Hold`), as macOS stops a scroll's momentum under resting fingers: its `onMomentumScrollEnd` once, where it is, with no scroll after; resting fingers are no drag (no `onScrollBeginDrag`: lifted unmoved, they began none; moving on, they are a scroll, which begins one). Android's touchscreen stops an `OverScroller` fling on a finger's `ACTION_DOWN`, which is also a drag's beginning; a touchpad's resting fingers are not yet a scroll, so OxyOS stops the glide as macOS does. Every scroll event (the scroll, the drag's begin and end, the momentum's) is stamped with when the host dispatched it (`timestamp`, performance.now()'s clock), as React Native's Android `ScrollEvent` takes `SystemClock.uptimeMillis()` when it is obtained, in whole milliseconds (React Native's C++ `ScrollEvent` holds a float of seconds, which since boot comes in steps of 31 ms, so the host sends the payload's `timestamp` as a double, as Android's does). Differences, stated: momentum events are sent whether JavaScript listens or not (Android sends them only with `sendMomentumEvents`, which the C++ props do not carry); gesture handlers do not see a touchpad's scroll as a finger; a wheel's notch is not animated, as macOS animates it. The velocity is measured on the events' device times (the protocol's `time_ns`), so a slow frame does not change it. `scenarios/touchpad-scroll.json` and `touchpad-scroll-scaled.json` check the drag, the velocity, a glide of Android's distance and one stopping at the end, each event once, and the wheel; `scenarios/touchpad-hold.json` and `touchpad-hold-scaled.json` every scroll event's `timestamp` against when it was dispatched, and a glide stopped by resting fingers. |
| Overscroll (`input.h`, `scroll-physics.h`, `overscroll.h`) | As Android 12's `ScrollView` stretches past its ends (`EdgeEffect`, `TYPE_STRETCH`, the default since Android 12; the glow before it is not drawn). A touchpad's drag that would go past an end pulls the stretch there by the whole move, a share of the view's size (`onPullDistance`, as `ScrollView.onTouchEvent` pulls it), the offset staying at the end and no scroll event sent (Android's `overScrollBy` clamps with an overscroll distance of 0); a move the other way takes the stretch back first (`releaseGlow`); a move clamped at an end forgets the velocity so far, as `ScrollView` clears its `VelocityTracker` then, so letting go there flings nothing. The fingers lifting let it go (`onRelease`), new fingers catch it where it is (fingers coming to rest too, letting it go again when they lift or move on), and a glide reaching an end strikes it with the glide's velocity (`onAbsorb`) and stops there. Released or struck, it springs back to rest once a frame of the window's display (`updateSpring`). Its amount is `EdgeEffect`'s (`dampStretchVector`), with its constants as recalled from AOSP's source, which is not at hand: the spring's natural frequency 24.657 and damping ratio 0.98, a strike's velocity times 13, rest under a thousandth of a pixel, and the stretch 0.016 of the pull plus 0.016 of (1 − e^(−pull·e/0.33)). `overScrollMode` is honoured as React Native's Android `parseOverScrollMode` reads it: `auto` stretches only a view whose content scrolls (`OVER_SCROLL_IF_CONTENT_SCROLLS`), `always` always, `never` never; the portable C++ props drop it, so the host's ScrollView descriptor keeps it beside each props (`overscroll.h`). A wheel's notch never stretches (Android's `ScrollView` does not stretch for a mouse). Differences, stated: the stretch is drawn as a uniform scale of the content along the axis, from the edge it is pulled past, by one plus its amount, where Android's render node stretches it with HWUI's stretch shader, more near that edge; one stretch per axis of a view (Android keeps one per edge, the other released when one is pulled); a scroll view's axis is the one its content scrolls along (OxyOS's ScrollView is Android's ScrollView and HorizontalScrollView at once). ## Drawing: Skia, as Android draws

Android draws a React Native view through `BackgroundStyleApplicator`'s drawables onto an `android.graphics.Canvas`, which is Skia; Chromium draws Bloom (react-native-web) with Skia too. The host draws with Skia as well ([ADR 0031](./adr/0031-gpu-buffers), decision 12, amended): Ganesh on Vulkan where the compositor shares a GPU, Skia's raster backend into shared memory otherwise, Skia built from source at the revision Chrome 156 stable ships. Each prop is drawn with the canvas calls React Native's Android code makes for it, in `CompositeBackgroundDrawable`'s order: outset `boxShadow`s (`OutsetBoxShadowDrawable`: the box grown by the spread and moved by the offset, blurred with a sigma of half the blur radius, never under the box itself), `backgroundColor` (`BackgroundDrawable`), `experimental_backgroundImage` (`BackgroundImageDrawable`), the border (`BorderDrawable`: per-side widths and colours, `solid`, `dashed` and `dotted`, elliptical corners, overlapping radii reduced as CSS reduces them), inset `boxShadow`s (`InsetBoxShadowDrawable`, within the padding box), the outline (`OutlineDrawable`); then the view's content and children, clipped to its padding box's rounded rectangle when it clips. Text keeps Android's layout (Minikin's line breaking, above) and is drawn by Skia from the same font files.

Fidelity is checked against Chromium: a gallery of Bloom's components (`sample/FidelityGallery.tsx`, its pages in `sample/fidelity-pages.json`), light and dark, at scales 1 and 1.25, drawn by Chromium through react-native-web (built as an Oxy application ships Bloom to a browser, with the host's own font files) and by the host, each component cropped from both and held under a threshold of its own (`tools/rn-host-spike/fidelity.py run … --check`, `scenarios/fidelity-thresholds.json`; `scenarios/fidelity*.json` are the host's half). Where Android's behaviour is not Chromium's, the host follows Android, and each such difference is listed below with its reason.

## What OxyOS does not provide

**Absent:** the call throws, and the host logs `TurboModule unavailable`.
- `ToastAndroid`, `Vibration`, `PermissionsAndroid`;
- `ShareModule`, `ActionSheetManager`;
- `DialogManagerAndroid`: `Alert.alert` and `Alert.prompt` throw. - the Expo modules Bloom does not need. Of those an Expo Router application's runtime looks for: `ExpoSplashScreen` (OxyOS shows no splash screen: expo-router's calls to it do nothing, as on the web), `ExpoUpdates`, `EXDevLauncher` and `ExpoGo` (a release build without updates or a development client), `ExpoFontUtils`, `ExpoSystemUI` (the root view's colour and the system bars; Stash only configures it), `RNSModule` (react-native-screens' native screens: an application whose routes use a native stack is not supported yet; Stash's use Expo Router's `Slot` and Bloom's AppShell), `RNVectorIconsManager` (an icon font rendered to an image), `FileSystem` (expo-file-system, its own work) and the Oxy SDK's own `OxyBackgroundSession`. Their packages find them missing and take their own fallbacks; calling one that has none throws.
- `ExpoImage` (expo-image): the host draws React Native's `Image`, not expo-image's view, so Bloom's images take React Native's `Image` (its own fallback when expo-image cannot load) and the Oxy SDK's surfaces that draw with expo-image (its `ExpoImage`, which imports it directly) fail when they are first loaded (`Cannot find native module 'ExpoImage'`; none is on Stash's signed-out screens). Drawing it needs expo-image's `ExpoImage` view (its `source` list, `contentFit`, `contentPosition`, `tintColor`, `placeholder`, `transition`, `blurRadius`, and its `onLoadStart`, `onProgress`, `onLoad`, `onError` and `onDisplay` events) and its module (`prefetch`, the caches, `loadAsync`'s image references), and remote images, which the host's `Image` does not load yet.

**Absent, and only React Native's own code calls them:** `SoundManager` (Pressability's touch sound) and `FrameRateLogger` (scroll performance logging). React Native skips them when they are missing; no API an application calls depends on them.

**Accepted with no effect, reported once:**
- *There is nothing to apply on OxyOS:* status bar style, colour and visibility (there is no status bar); the default back-press handler; red-box messages.
- *Capabilities OxyOS does not have yet:* forcing or allowing RTL; setting the colour scheme; and the legacy tag-based `setAccessibilityFocus`.

Changing any of these is a change to this page and to its scenario.

## Expo applications from their own checkout

OxyOS runs an Oxy application from the same source as its web and native builds ([ADR 0015](./adr/0015-application-model)); its OxyOS build is the sample's bundle (`sample/bundle.mjs`, `sample/metro.config.js`), which takes the application from its checkout as it takes Bloom from `BLOOM_DIR`. One build holds one application: `OXYOS_APPLICATION_DIR` names its Expo project and `OXYOS_APPLICATION_MODULE` the module it registers as (`sample/oxyos/application-build.js`); without them the bundle has no application and builds as before. `sample/packages.mjs` builds each application named by its own checkout's variable this way, its module its package's `entry.module`: `STASH_DIR` (Stash's `packages/frontend`, module `Stash`) and `ATLAS_DIR` (Atlas's, module `Atlas`), each when it is given; adding another is a line in its `CHECKOUTS` and a package description.

- **Its root, as `expo-router/entry` runs it** (`sample/oxyos/application.js`): `@expo/metro-runtime`, Expo's runtime, then the App of expo-router's qualified entry, `ExpoRoot` over expo-router's own `_ctx` (the `require.context` of the application's `app/`, its `EXPO_ROUTER_APP_ROOT` replaced by babel-preset-expo's router plugin for the application's project root, which Metro's workers get as `EXPO_PROJECT_ROOT`), registered as its module instead of Expo's `main`. Around it only what the runtime owns: Bloom's platform adapter (`PlatformSurfaceProvider value={oxyosSurfaces}`), which the application's own `BloomProvider` keeps (Bloom #525), and, for a launch the image's policy gives `store` (Atlas), the machine's installer registered in the application's own Oxy SDK before its code runs (`sample/oxyos/store-registration.js`: `@oxy.so/core`'s `setStoreInstaller`, resolved from the application's tree so it is the copy the application reads; the installer is the framework's `sample/oxyos/store-installer.js`, over `OxyOSSystem`; [ADR 0030](./adr/0030-installing-applications), decision 9). The launch says its grants in `OXYOS_APP_GRANTS`; an application whose SDK has no such seam (older than `@oxy.so/core` 7.10) builds the registration as an empty module. Its gesture root, safe area, Bloom and the Oxy SDK are its own `app/_layout`. A router root other than `app/` is refused when bundling. One bundle holds one Expo Router application: expo-router's `_ctx` is one module.
- **One copy of each package.** What the Bloom checkout's tree has resolves from there when it is a version its requester accepts (the range its package declares): one React, one React Native, one Reanimated, the platform's runtime matching the host's native code. Bloom itself always comes from `BLOOM_DIR`. Everything else comes from the application's own `node_modules`, and so does a package the Bloom tree has only in a version its requester does not accept: Bloom's development tree holds expo-linking 56 beside expo-router 58, which asks for 58, and that request resolves from the application rather than to the wrong version (the Bloom tree's own requests too). Such a package can then be in the bundle twice (expo-constants, which expo-linking 58 asks for in a newer version than Bloom's tree has); each copy reads the same native module. Built against a runtime's framework (ADR 0030, decision 17), an application gets no copy of its own: a package the framework has is exactly the framework's version, and an application whose dependencies do not accept it stops the build; the framework itself holds one copy of each package (the newest its requesters accept), and two files with one key stop its build.
- **What its own Expo build takes from its project**, taken the same way, from its own tree: its `.env` files for a production build (`@expo/env`; a variable already set wins), so its `EXPO_PUBLIC_*` variables are inlined; its TypeScript `paths` (`@/lib/config`, read by its own TypeScript) for its own sources; NativeWind's `className` on its `react-native` imports (react-native-css's resolver with `globalClassNamePolyfill`, as `withNativeWind` sets it), Bloom's own imports staying as the platform runs them; its `global.css` through the same Tailwind and react-native-css pipeline, its `@import`s and `@source`s resolved from its own tree (`@oxy.so/app-preset/base.css`); Oxy's build id (its commit, `OXY_BUILD_ID`, as `@oxy.so/app-preset` names a production build), which the Oxy SDK busts its persisted caches on; and its public app config (`expo/config`'s `getConfig`, as expo-constants' `getAppConfig` does), written beside the bundle where `ExponentConstants` reads it. Its code is compiled by the platform's Babel (babel-preset-expo from the Bloom tree), and with the React Compiler when its `experiments.reactCompiler` asks for it, as Expo CLI asks for it: the `reactCompiler` transform option, which Expo's transformer gives the preset as its caller's `supportsReactCompiler`, so the preset adds the compiler with its own options. `oxyos/babel-transformer.js` gives it to the application's own sources alone: the preset would add it to every file outside a `node_modules`, the platform's own modules among them, which the application's own build takes from `node_modules` and never compiles.
- **The Oxy SDK** mounts and resolves signed out. On OxyOS the account is the platform's and applications are to get their session from it ([ADR 0020](./adr/0020-oxy-account-login), decision 6), which needs the SDK's host mode (Oxy ADR 0052, a draft): until then the secure store keeps nothing and says so in the log when the SDK restores its session, and an attempt to keep a credential fails with that reason. Without its client id (`EXPO_PUBLIC_OXY_CLIENT_ID`, from its environment) the SDK does not try to restore a session at all.
