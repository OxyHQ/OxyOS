# React Native's Android implementation on OxyOS

OxyOS is not Android. The native Bloom host (`tools/rn-host-spike`) nevertheless runs **React Native's own modules in their Android implementation**. React Native supports two native platforms, and the host implements the native interfaces of one of them, Android, instead of maintaining copies of React Native's platform branches. This page is the contract for that adaptation.

**Rule:** a React Native API that OxyOS does not provide fails visibly. Its native module is absent and the call throws, or its promise rejects. It never pretends to succeed and never leaves its caller waiting. Where React Native's own Android code would skip a missing module silently, OxyOS overrides it to fail (`sample/oxyos/`).

`scenarios/android-adaptation.json` (`regress.py`; the probe is `sample/AndroidProbe.tsx`) checks one call per row:
- **unavailable:** `ToastAndroid`, `Vibration`, `PermissionsAndroid`, `Linking.openURL`, `Share`, `Alert.alert`, `Alert.prompt` and `getAndroidID`;
- **rejected:** `Image.getSize` of a remote image;
- **answered:** `AccessibilityInfo`'s timeout and screen reader, `Appearance`, `Dimensions`, `I18nManager.isRTL` and `AppState`;
- **accepted with no effect:** `StatusBar.setHidden`, `I18nManager.forceRTL` and `Appearance.setColorScheme`.

Rows not in this list are not checked.

`scenarios/network.json` (the probe is `sample/NetworkProbe.tsx`, against a local server `regress.py` runs) checks `fetch` and `XMLHttpRequest`: JSON, text, a 404, request and response headers, a POST body, a redirect, bytes read back as an `ArrayBuffer`, a multipart form, an abort, a refused connection, a timeout, and a text body as it arrives with a character split between two reads. A file in a multipart body fails visibly.

## What is reused from React Native's Android implementation

| Part | How |
| --- | --- |
| Core JavaScript | React Native's own modules resolve `Platform.android.js` and take their Android branches. Their `.android.js` files are used where no OxyOS override exists (`sample/metro.config.js`). Everything else, including the `Platform` that `react-native` exports to apps and to Bloom, reports `oxyos`. |
| Native component names, view configs and commands | `AndroidTextInput` (Bloom's `TextField`), `AndroidHorizontalScrollView` (the `ScrollView` component) and `AndroidHorizontalScrollContentView`. |
| C++ shadow nodes, props and state | The Android text input's, built unchanged from a private copy patched with the `RN_SERIALIZABLE_STATE` guard upstream lacks (`patches/`). The horizontal scroll content view's is built unchanged. |
| TurboModule specs | The Android specs (for example `PlatformConstants`), answered by the host's own modules below. |
| Events | Android's text-input events (`topChange`, `topKeyPress`, `topSelectionChange`, `topSubmitEditing`, `topFocus`, `topBlur`, `topEndEditing`) with Android's payloads. |
| Touchpad pinch (`input.h`) | As Android 14's touchpad stack gives one to applications (inputflinger's `GestureConverter`): two fingers around the pointer, starting `INITIAL_PINCH_SEPARATION_PX` (200 of the display's pixels) apart side by side, finger 0 down then finger 1, both moving as the spread changes, then finger 1 up and finger 0 up, as touches to React Native (the target under finger 0) and as fingers (RNGH's pointer type 0) to gesture handlers. One difference, stated: Android's fingers never turn, and these turn as libinput reports the user's fingers turning, so rotation handlers see a touchpad's twist. A pinch libinput cancels cancels both fingers. `scenarios/pinch.json` checks it. |
| Assets | Android's resource layout (`drawable-*`, `raw/`), computed by React Native's own path helpers. |
| Release bundle | Hermes bytecode, as an Android release build ships it: Metro's output compiled by the `hermesc` of the Hermes the host runs, with the Android Gradle plugin's `-emit-binary -O` (`sample/bundle.mjs` with `HERMESC`, as `build.sh` sets it). A source bundle still runs, but Hermes then parses and compiles it while the app starts. Stack traces give bytecode offsets, as an Android release build's do without its source map. |

## What OxyOS implements

| Module | OxyOS behavior |
| --- | --- |
| `PlatformConstants` | `Release`/`Model` are `OxyOS`. `Version` is 36: not a device API level, but the level whose React Native code paths the host follows (React Native 0.88's target SDK). Core uses it only to trust keyboard events, and OxyOS has no software keyboard and sends none. `getAndroidID` throws ("OxyOS has no Android ID"). |
| `DeviceInfo`, `SourceCode`, `AppState`, `Appearance` | The window's size and scale; the bundle URL; always active; the light scheme. |
| `AccessibilityInfo` | Reports no assistive technology and no reduced motion; the recommended timeout is the one asked about, as on Android without a preference. `sendAccessibilityEvent(view, 'focus')` (through Fabric) moves the host's accessibility focus, as Android's accessibility focus: to the view, or to the first accessible node inside it. The host publishes each surface's tree to the compositor for a screen reader ([ADR 0003](./adr/0003-accessibility-protocol)), and a screen reader's activation reaches JavaScript as Android's accessibility click (`onClick`, which Pressability turns into `onPress`). `announceForAccessibility` reaches the screen reader through the compositor, at once; its other actions (increment, decrement, custom actions by name, scrolling, dismissing, a selection) reach JavaScript as Android performs them ([ADR 0003](./adr/0003-accessibility-protocol)). |
| `Intl` (`intl.h`, `crates/oxyos-intl`) | Hermes has `Intl` on Android from the platform; OxyOS's Hermes has none, so the host installs one before the bundle runs: `Intl.DateTimeFormat` and `Intl.NumberFormat` (`format`, `formatToParts`, `resolvedOptions`, `supportedLocalesOf`), `Intl.getCanonicalLocales`, and `Date`'s and `Number`'s `toLocale*String` built on them, with ECMA-402's option processing (`intl.js`) and ICU4X's CLDR data for the formatting. The default locale is the session's (`LC_ALL`, `LC_MESSAGES`, `LANG`), the default time zone the system's, and named time zones come from the system's tz database. An option not supported yet (such as compact notation or `timeZoneName`) throws a `RangeError` saying so; `Collator`, `PluralRules`, `RelativeTimeFormat`, `DisplayNames`, `Locale`, `ListFormat` and `Segmenter` are not provided yet and are undefined, so feature detection finds them absent. Differences from ICU's own formatting, from ICU4X 2: a format has one width (taken from `month`, else `weekday`, else `era`) where ECMA-402 gives each field its own, and the month's text or number follows the locale's date lengths (German's `{ day: 'numeric', month: 'short' }` is `29.10.`, not `29. Okt.`); digits are always Latin and the calendar Gregorian; `useGrouping: 'always'` groups as `auto`. `scenarios/intl.json` checks every row against ICU 78.3 with CLDR 48 (Node's `formatToParts`), the German one as that difference. |
| `ExceptionsManager` | Prints the error and its stack. |
| `Image` | What Android's `ReactImageView` does: each mounted Image loads its source, at the size it is drawn, on threads of its own (`crates/oxyos-image`, PNG and JPEG decoded in Rust, an embedded ICC profile such as Display P3 converted to sRGB, reduced by averaging), and the view draws it by `resizeMode` (`cover`, `contain`, `stretch`, `center`, `repeat`, `none`), rounded with its corners and tinted with `tintColor` as Android's `SRC_IN` filter. Its load events are Android's: only when JavaScript listens (`shouldNotifyLoadEvents`), `loadStart`, then `load` with the bitmap's size in pixels or `error`, then `loadEnd`. Views showing the same picture share it. Sources are files: `file://` (a release bundle's assets, resolved to its drawable folders, as Android resolves them when the bundle is loaded from the file system) and absolute paths. Not supported yet, and failing with a message: remote images, `data:` URIs, other formats (GIF, WebP), and `blurRadius` (drawn unblurred, reported once). A truncated JPEG shows what arrived, as Android's decoder does. `scenarios/images.json` checks the events and the output's pixels. |
| `ImageLoader` | `getSize` and `getSizeWithHeaders` read a file's headers; `prefetchImage` succeeds for a readable local image, which needs no fetching; `queryCache` reports nothing cached; `abortRequest` has nothing to abort. Remote images are refused, as above. |
| `Networking` (`fetch`, `XMLHttpRequest`) | Requests run in Rust (`crates/oxyos-net`, through the host's one Rust library): TLS with rustls against the system's certificates, gzip and brotli, a timeout over the whole request, and one cookie jar for the process, used only by requests `withCredentials`. Redirects are followed as browsers do (up to 20; a 303, or a 301 or 302 after a POST, goes on as a GET without its body; `Authorization` is not carried to another origin), and each hop keeps and sends its own cookies. A connection lost before any response is tried again, up to three times, as Android's OkHttp does. The answers are Android's events, each with its arguments as one array; an incremental body (text only, as on Android) never splits a character. Every failure's reason is logged (`[host] network request N failed: ...`), since `fetch` reports only "Network request failed". Not supported yet, and failing the request: files in multipart bodies and bodies from a URI. The jar has no public suffix list, so a cookie for a whole public suffix is not refused. |
| `OxyOSFiles` (`files.h`, [ADR 0027](./adr/0027-files)) | OxyOS's own module, not React Native's: the user's home and mounted volumes for an application's window (never the shell's or the login screen's), through `crates/oxyos-files`. `request(json)`, answered by `OxyOSFilesAnswer` and watched changes said by `OxyOSFilesChanged`, each the service's JSON; the service starts with the first request and answers every request it cannot run with its reason. An application uses it through its own model (Files: `sample/FilesApp.tsx`). |
| Expo modules (`sample/oxyos/expo-adapter.js`) | `expo-font` and `expo-asset` load bundled files. `expo-clipboard` is the OS clipboard ([ADR 0007](./adr/0007-clipboard)): its calls carry the serial of the latest key or press the app received, so they work only while the app has focus and the user just acted (a refused read gives ""); URLs are text and images are refused; `onClipboardChanged` fires when the content changes. `expo-notifications` posts to the session ([ADR 0026](./adr/0026-notifications)): notifications presented now (a `null` trigger) with their data and a category's actions, the handler asked as Expo asks it, responses to the listeners and `getLastNotificationResponse` once each; scheduled triggers, push tokens and background tasks are refused. `expo/fetch` is not provided: bundles for OxyOS set Expo's `EXPO_PUBLIC_USE_RN_FETCH=1`, so `fetch` is React Native's, above. `EXPO_PUBLIC_*` variables are inlined when the bundle is built, as Expo's production build inlines them. Expo's native views come through `getViewConfig`: `expo-blur`'s views are host components (below), and any other Expo view fails with a message naming it. |
| `BlobModule`, `FileReaderModule` | Blobs are kept in the host: a response read as a blob, and blobs built from parts. `FileReader` reads them as text or as a data URL. |
| Fonts (`OxyOSFontRegistry`, for `expo-font`) | Registers a font only if FreeType can open it. |
| Fabric | View, Paragraph, ScrollView (native offsets), text input, popups (`OxyOSPopupView`), `Modal`, events, Reanimated and Worklets. |
| Pointer presses (`input.h`) | Every mouse button's press and release is a W3C pointer event (`pointerdown`, `pointerup`) to the view under the pointer, bubbling, with its `button` (0 primary, 1 auxiliary, 2 secondary), the `buttons` held and the modifiers (Shift, Ctrl, Alt, Meta), as Android's `JSPointerDispatcher` sends a mouse's; the primary button is also the touch it was. React Native's Android base view config lists their bubbling events but not their props, so no view could listen (Fabric's pointer events processor emits only to a listening path): OxyOS's override adds `onPointerDown`, `onPointerUp` and their capture phases, as its iOS config has them (`sample/oxyos/Libraries/NativeComponent/BaseViewConfig.oxyos.js`). A secondary press is no touch, so it presses nothing and opens a context menu (Bloom's, in a compositor popup at the press, [ADR 0027](./adr/0027-files)). `scenarios/files.json` checks them. |
| Pointer shape (`input.h`) | As Android resolves a pointer icon, from the view under the pointer up to the root, the first that sets one: an editable text input shows the text shape (Android's `EditText`), and a view's `cursor` style its own. Android knows `pointer`, the hand; the other CSS cursors React Native parses take the shape that is theirs (resizes, move, grab, wait, not allowed, help, crosshair, zoom), which Android ignores; `none` shows the arrow. The host tells the compositor each surface's shape when it changes (`scenarios/sample.json`, `scenarios/sheet.json`). |
| Transforms (`renderer.h`) | A view's `transform` (translation, scale, rotation and skew, about its centre as Android's default pivot is, or its `transformOrigin`) applies to its subtree as Android applies a view's matrix: drawn through it, hit through its inverse (a view scaled to nothing is under no point), and damaged where its transformed frame is. A view with more than a translation is drawn as a layer of its own, its subtree at the resolution its largest scale needs (up to four times the display's), mapped onto the window and sampled bilinearly. The frames measured (gesture handlers, text inputs, popups' anchors and touch locations) are moved by where the transform takes the centre, at the frame's size. Not yet: perspective (a 3D transform is drawn as its projection onto the screen, reported once). `scenarios/transform.json` checks a moved, a scaled and a turned view, and a quarter turn that keeps the bounding box. |
| `NativeAnimatedModule` (`native-animated.h`) | React Native's C++ Animated (`AnimatedModule`, `NativeAnimatedNodesManager`), as Android runs it with `cxxNativeAnimatedEnabled`: stepped once a frame on the host's loop while it animates, its props set on the mounted views between commits as Android's mounting layer sets a native view's, layout props and finished values committed to the shadow tree. `updateAnimatedNodeConfig`, which that implementation leaves empty, is reported once. `scenarios/native-animated.json` checks it. |
| `requestAnimationFrame` (`animation-frames.h`) | Once a frame, as Android's Choreographer runs it, instead of React Native's bridgeless zero-delay timer: a frame begins when the compositor has answered the window's previous one and a refresh of the window's display has passed (the compositor's `Refresh`, [ADR 0018](./adr/0018-several-displays): 16.7 ms at 60 Hz, 8.3 at 120; the display's frames alone without a window). Callbacks get the frame's time on `performance.now()`'s clock, each as a task of its own; `cancelAnimationFrame` holds inside a frame too. Other timers still fire when due, not on frames as Android's registry fires them. |
| `Modal` (`modal.h`) | Android gives a modal a window of its own over the activity's; OxyOS draws its subtree over the window's content, at the window's origin and size (its state, as Android sets it from the screen), and gives it the window's input: nothing under it is reached. `onShow` when it appears; Escape, the desktop's back, sends `onRequestClose` to the topmost one. A modal not `transparent` is drawn on white. Its `animationType` animates it as Android animates its window, with React Native's own animations for it (`catalyst_slide_up`, `_slide_down`, `_fade_in`, `_fade_out`): for 200 ms (`config_shortAnimTime`), `slide` moves it up from below the window and back down (accelerating, then decelerating), `fade` fades it in and out (accelerating). A modal closing is drawn from its last frame while it animates out, as the window manager animates a dismissed dialog's window. Not yet: an accessibility tree of its own (its content is published with the window's), and Android's animation scale setting (the animations always take 200 ms). `scenarios/sheet.json` checks it with Bloom's bottom sheet, `scenarios/modal.json` its animations: each one's position or alpha frame by frame, and the page or the modal at the end. |
| `expo-blur` (`expo-blur.h`) | As Android's: its Android modules run (`sample/metro.config.js`), so `BlurTargetView` is its own native view, never one Fabric flattens away. A `BlurView` with a `blurTarget` and a blur method other than `none` (Dimezis' `BlurView` on Android) is the target's content under it, drawn afresh (never what the canvas holds, which outside the damage is the last frame, the blur included), blurred with a Gaussian of radius `intensity / blurReductionFactor` logical pixels (three box blurs, each a running sum), then its tint at the alpha Android's `TintStyle` gives its intensity, clipped to it and its rounded corners. The blur reads three radii around each pixel, so a change that near it damages it too. Without a target, or with the method `none`, it is its tint alone. Dimezis' downscaling of the target for speed is not reproduced. `scenarios/material.json` checks the blur's ramp over a black and white edge against the Gaussian's integral, its tint and clip, and the method `none`, sharp. |
| `RNCMaskedView` (`masked-view.h`) | React Native's MaskedView (`@react-native-masked-view/masked-view`), as its Android view draws: the first child is the mask; the other children are drawn on their own and kept by the mask's alpha (`DST_IN`), within the mask's opaque box alone. The shell takes it through its platform (`oxyosShell.Masked`, which renders the package's structure: the mask in a first child filling the view, then the children). `scenarios/material.json` checks an opaque and a half transparent mask. |
| `RNGestureHandlerModule` (`react-native-gesture-handler`, `gesture-handler.h`) | Android's orchestrator and handlers (RNGH 3.3.0), ported to Rust (`crates/oxyos-gestures`): pan, tap, long press, fling, manual, pinch and rotation handlers (with RNGH's own `ScaleGestureDetector` and `RotationGestureDetector`), `waitFor`, `simultaneousWith` and `blocksHandlers`, hit slop, `manualActivation`, touch events (`onTouchesDown` and the rest), and JavaScript's state changes through RNGH's own runtime bindings (`_setGestureStateSync`, `_setGestureStateAsync`), built unchanged. Timers are deadlines the host ticks. The primary mouse button's touch, and a touchpad pinch's two fingers, reach the handlers after React Native, hit-tested as RNGH's orchestrator traverses (views under 10 % opacity passed over). What they recognize goes where Android sends it: worklet handlers to Reanimated, JavaScript ones as device events; a handler activating cancels React Native's touch (`cancelsJSResponder`) and a text input's drag selection. Velocity is a second-degree least-squares fit of the last 100 ms, as Android's default `VelocityTracker`. Differences, reported: the native-view handler begins and fails (no native view takes over a gesture); the hover handler is refused; Animated's native driver, the newer API's native detectors and mouse buttons other than the primary are reported once. A pinch sends `scale`, `focalX`, `focalY` and its `velocity` (scale per second), a rotation `rotation`, `anchorX`, `anchorY` and its `velocity` (radians per millisecond, as Android's detector divides by milliseconds); they get two fingers from a touchpad pinch (above). `scenarios/shell-overview.json`, `scenarios/sheet.json` and `scenarios/pinch.json` check it. |

## What OxyOS does not provide

**Absent:** the call throws, and the host logs `TurboModule unavailable`.
- `ToastAndroid`, `Vibration`, `PermissionsAndroid`;
- `IntentAndroid` / `LinkingManager` (`Linking`);
- `ShareModule`, `ActionSheetManager`;
- `DialogManagerAndroid`: `Alert.alert` and `Alert.prompt` throw. React Native's Android `Alert` returns silently without that module, with no dialog and no callback, so OxyOS overrides it (`sample/oxyos/Libraries/Alert/Alert.oxyos.js`). Bloom's own alert surfaces, with `Alert`'s signature, draw their dialogs in the application;
- `WebSocketModule` (`WebSocket`), and with it `BlobModule.sendOverSocket`, which throws;
- the Expo modules Bloom does not need.

**Absent, and only React Native's own code calls them:** `SoundManager` (Pressability's touch sound) and `FrameRateLogger` (scroll performance logging). React Native skips them when they are missing; no API an application calls depends on them.

**Accepted with no effect, reported once:**
- *There is nothing to apply on OxyOS:* status bar style, colour and visibility (there is no status bar); the default back-press handler; red-box messages.
- *Capabilities OxyOS does not have yet:* forcing or allowing RTL; setting the colour scheme; and the legacy tag-based `setAccessibilityFocus`.

Changing any of these is a change to this page and to its scenario.
