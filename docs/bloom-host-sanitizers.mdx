# Sanitized Bloom hosts

A crash in the Bloom host is found with the tools that make it certain, not by retrying: a host
and a Hermes built with a sanitizer, each in a build directory of its own beside the toolchain
(`W=~/oxyos-build/rn-host-menubar`, its environment `~/oxyos-build/stab/env.sh`, the host's CMake
variables `~/oxyos-build/stab/cmake-vars.txt`). None of this is installed or shipped: a sanitized
runtime is a runtime directory the regression scenarios run (`regress.py --runtimes`).

## The crash report

A fatal signal in a host (`SIGSEGV`, `SIGBUS`, `SIGILL`, `SIGFPE`, `SIGABRT`) writes to the
session's log, before the process ends with 128 + the signal:

```text
[host] fatal signal 11 (code 1) at address 0x..., on thread 1234 'oxyos-bloom-hos'
[host] rip ... rsp ... rax ... rdx ... rdi ... (every general register)
.../oxyos-bloom-host(+0x49e958) [0x...]
.../lib/libhermesvm.so(+0x3180c9) [0x...]
```

The thread's name tells the JavaScript thread (the main one, named after the executable) from
Hermes' collector (`hades`) and the image decoders (`oxyos-image-N`). The registers tell a bad
pointer from a bad index. The scenarios run with `MALLOC_PERTURB_=165` (`regress.py`), so memory
read after it was freed holds `0xa5a5a5a5a5a5a5a5` and memory never written `0x5a5a5a5a5a5a5a5a`:
either in a register at the fault names the bug's kind. The handler runs on a stack of its own,
so a stack overflow on the JavaScript thread is reported too.

The frames are offsets into the runtime's objects. The host and `libreactnative.so` of a deploy
run are its build directory's (`$W/<host dir>`); `libhermesvm.so` is `$W/hermes-build`'s, built
with its debug information as React Native's Android build builds it
(`tools/rn-host-spike/build-hermes.sh`, run by `build.sh`); the runtime's copy is the same library
stripped of it. Functions and lines come from the build's:

```sh
addr2line -f -C -i -e $W/hermes-build/lib/libhermesvm.so 0x3180c9
```

## Sanitizers

`OXYOS_SANITIZE=address`, `thread` or `undefined` instruments everything the host's CMake builds:
the host, React Native, folly, glog, the worklets, Reanimated, the SVG and gesture handler cores.
Hermes is built apart, by `build-hermes.sh` into a build directory of its own with its own
option, and with the same compiler as the host (Clang 19 from the toolchain), whose sanitizer
runtime the two must share. The sanitizer runtimes and `llvm-symbolizer` are Debian's
`libclang-rt-19-dev` and `llvm-19`, unpacked into `$W/clang` (`apt-get download`, `dpkg-deb -x`).

```sh
. ~/oxyos-build/stab/env.sh; export PATH=$W/tools/bin:$PATH
tools/rn-host-spike/build-hermes.sh ~/Oxy/Bloom/node_modules/react-native $W hermes-build-tsan \
  -DHERMES_ENABLE_THREAD_SANITIZER=ON
args=$(sed "s|^OXYOS_CLIENT_LIB=.*|OXYOS_CLIENT_LIB=$PWD/target/release/liboxyos_client_ffi.a|; \
  s|^HERMES_BUILD=.*|HERMES_BUILD=$W/hermes-build-tsan|; s|^|-D|" ~/oxyos-build/stab/cmake-vars.txt | tr '\n' ' ')
CC=$W/clang/usr/bin/clang-19 CXX=$W/clang/usr/bin/clang++-19 cmake -S tools/rn-host-spike -B $W/host-tsan \
  -G Ninja $args -DCMAKE_BUILD_TYPE=RelWithDebInfo -DOXYOS_SANITIZE=thread
ninja -C $W/host-tsan oxyos-bloom-host
cmake --install $W/host-tsan --prefix RUNTIMES/1
cp -a WORK/runtimes/1/framework WORK/runtimes/1/runtime.json RUNTIMES/1/   # the framework the packages were built on
```

For AddressSanitizer, `-DHERMES_ENABLE_ADDRESS_SANITIZER=ON` and `-DOXYOS_SANITIZE=address`; for
UndefinedBehaviorSanitizer, `HERMES_EXTRA_FLAGS="-fsanitize=undefined -fno-sanitize=vptr"` and
`-DOXYOS_SANITIZE=undefined`. A host built with AddressSanitizer also builds
`oxyos-turbo-module-cache-test`, which keeps a C++ TurboModule's method past a collection of its
module's object (`$W/host-asan/oxyos-turbo-module-cache-test`; `--uncached` shows the use after
free the runtime's module cache prevents, `turbo-module-cache.h`).

The scenarios then run on `RUNTIMES` with the sanitizer's options in the environment, which the
compositor passes to every host:

```sh
ASAN_OPTIONS=detect_leaks=0:detect_odr_violation=0:log_path=LOGS/asan \
TSAN_OPTIONS="report_signal_unsafe=0 log_path=LOGS/tsan" \
  python3 tools/rn-host-spike/regress.py tools/rn-host-spike/scenarios/displays.json \
  --offscreen target/release/oxyos-offscreen --runtimes RUNTIMES --packages WORK/packages
```

- `detect_odr_violation=0`: folly is linked into both `libjsi.so` and `libreactnative.so`, as
  React Native's Android build links it, and AddressSanitizer reports its globals twice.
- ThreadSanitizer reports races in the Rust decoders and channels (`jpeg_decoder`,
  `std::sync::mpmc`, `oxyos_image`): the Rust code is not instrumented, so their own
  synchronisation is invisible to it. A report with a C++ or Hermes frame on both sides is real.
- A sanitized host is slower: the scenarios' timing bounds fail, which says nothing; a sanitizer's
  report, a fatal signal or a JavaScript error does.

## Collecting on every allocation

`OXYOS_HOST_GC_SANITIZE=RATE` makes each allocation collect the young generation and move every
object in it, with probability `RATE` (0 to 1), in a Hermes built with
`build-hermes.sh` and `-DHERMESVM_SANITIZE_HANDLES=ON` (and `-DCMAKE_BUILD_TYPE=Debug` for its assertions and heap
checks): a value held across a collection without a root, or freed while reachable, then fails at
the first use instead of rarely. Any other Hermes ignores it. A host at 0.01 takes about ten
seconds for its first frame, beyond the compositor's launch deadline: rates of 0.001 to 0.005
start, and the headless mode (`oxyos-bloom-host BUNDLE MODULE OUT.png`) takes any rate.
