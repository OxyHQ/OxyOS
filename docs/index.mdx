# OxyOS

OxyOS is being rebuilt as a native Linux platform: an Oxy display compositor and protocol, an application runtime that hosts the actual BloomUI, and no X11, XWayland or Wayland in the target session.

<Badge>Debian Trixie</Badge> <Badge>Foundation only</Badge>

## Status

- The root Rust workspace is a headless foundation: a schema-generated experimental protocol (version 2), compositor policy for surface roles, popups, input, focus and the lock primitive, and a two-process metadata probe. The compositor session itself drives no display yet. `oxyos-gpu` composes frames on the CPU and on Vulkan, and `oxyos-kms` shows them on a real output through DRM/KMS ([ADR 0004](./adr/0004-gpu-composition)). The Bloom host renders Bloom offscreen.
- `config/` builds a console-only Debian base system. There is no graphical session, and no OxyOS image is published until the native session is in it. The base is built, boot-tested in QEMU and audited locally (`tools/image/`); how OxyOS will be installed is [ADR 0022](./adr/0022-installing-oxyos).
- The earlier React/Tauri shell on labwc/greetd is retired. See [Retired desktop stack](./retired-desktop-stack).

The official website is [oxy.so/os](https://oxy.so/os), served by the [OxyHQ/website](https://github.com/OxyHQ/website) repository.
